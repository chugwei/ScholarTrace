# 科研真实性与数据安全

## 真实性规则

- 论文、DOI、作者、年份、页码、引文和原文片段必须来自可核验来源。
- 文献进入正式证据集前必须经过项目级审批；噪声库检索结果不能自动成为证据。
- LLM 只能生成结构化候选，校验失败或来源不足时必须降级为待验证状态。
- 实验结论必须绑定代码 Git SHA、数据版本、配置、环境、随机种子、Checkpoint、评估脚本和 MetricResult。
- 图表必须绑定输入数据、生成脚本、图表规格和输出哈希。
- 论文重要 Claim 必须绑定文献证据或实验结果；证据不足时标记 `insufficient`。
- 真实现场验证必须与训练、验证、测试、合成、Fixture、离线和实验室结果分开记录。

## 数据与秘密边界

Git 不保存以下内容：

- `.env`、API Key、Token、Cookie、密码或凭据；
- 真实用户数据库和个人身份信息；
- 未获授权的论文全文；
- 私有原始数据、正式标注、模型权重或大型运行产物；
- 本机绝对路径写入可移植配置或示例产物。

外部文件必须先复制到 staging，正式输入默认只读。发布采用“草案 → 校验 → 预览 → 人工确认 → 原子发布”，失败时保留旧产物和准确错误。

## M0 Fixture 声明

M0 Fixture 全部为脱敏、合成的项目描述，只用于 Schema、安装和回归测试。它们不包含真实论文、真实实验指标、真实个人信息或现场验证证据。
