# ADR 0028：以可验证交付树为前提进行监控与回滚

- 状态：accepted
- 日期：2026-08-11
- 范围：M12.4 Staging 监控、release pointer、回滚与校验和重建

## 决策

监控层只负责记录健康端点的可观察状态，不把 `200 OK` 当作模型或科研结果正确。发布层在激活前必须验证 Delivery Manifest；active、previous 和 history 通过原子 JSON 替换保存。激活失败时保留原 active 指针，回滚只在存在已验证的 previous release 时执行。

交付包的 `SHA256SUMS.txt` 由 Manifest 以相对路径排序后重建，并排除自身，避免手工顺序和自引用造成不一致。所有操作保留 manifest SHA-256 和 release id，便于审计。

## 理由

部署故障既可能来自服务不可达，也可能来自交付文件被改写。把健康探针和交付树验证分开，可以区分“服务活着”和“输入/版本可信”；先验证再切换指针则避免坏版本覆盖可用版本。

## 后续影响

M12.5 仍需记录真实场景证据、伦理与现场验证；M12.6 需要在独立环境复跑安装、部署、回滚和清单校验。生产级指标、告警后端和多节点一致性不由本地 `ReleaseStore` 自动提供。
