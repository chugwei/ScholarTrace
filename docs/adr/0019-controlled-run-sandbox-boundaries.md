# ADR 0019：受控实验执行的沙箱边界

## 状态

已接受（M8.1）。

## 背景

实验运行可能包含用户提供的脚本、数据路径和模型产物。把命令拼接成 shell 字符串，或直接让进程写入正式 Artifact 目录，会引入命令注入、路径逃逸和失败产物覆盖风险。M7 的 Run Manifest 只负责导入与 provenance 校验，不能替代执行边界。

## 决策

- 执行请求只接受 `argv` 列表，不接受 shell 命令字符串；`shell=False` 是后续执行器的固定约束。
- 可执行文件使用显式白名单，Python 禁止 `-c` 和未批准的 `-m` 模块；shell 元字符、NUL 和换行直接拒绝。
- 工作区、输入和输出使用相对路径契约；运行器以后端特定的 per-run staging 目录工作，正式产物目录不作为进程工作目录。
- Docker 后端使用无网络、只读工作区、独立可写输出卷、内存/CPU/PID 限制。Docker 不可用时不会伪装成 Docker 验收通过，测试只验证确定性命令构造。
- 运行请求必须绑定 frozen `ExperimentPlan` 的矩阵行，并在 SQLite 中以 `queued` 记录其不可变身份。

## 后果

这套边界牺牲了一些任意脚本的便利性，但使失败运行不会默认修改正式结果，也让命令、计划和资源限制可审计。M8.2 仍需实现进程生命周期、取消、超时和 staging 产物发布；本 ADR 不宣称这些能力已经完成。
