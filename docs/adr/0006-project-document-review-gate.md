# ADR 0006：项目文献必须经过显式审核门禁

- 状态：已接受
- 日期：2026-08-11
- 范围：M4.1 项目文献关联与相关度排序

## 背景

M3 的全局目录允许噪声、解析失败和只含元数据的条目。目录搜索命中不能证明文献与某个研究问题相关，也不能证明它可以作为论文证据。若把目录条目直接交给检索或生成流程，项目之间的判断会互相污染，失败文件也可能进入证据链。

## 决策

项目与文献之间使用 `ProjectDocument` 关系保存独立状态：新关联为 `candidate`，人工审核后只能变为 `approved` 或 `rejected`。审核同时保存 0–1 相关度、理由、审核者和 UTC 时间。后续正式项目检索只能读取显式 `approved` 关联。全局 `Document` 不因项目决定而修改。

候选排序使用本地、确定性的 metadata token overlap，仅作为人工审核排序辅助。失败或不可搜索文献不得批准；空白理由和越界分数拒绝提交。Schema 变化通过 Alembic 0005 管理，并验证回滚路径。

## 取舍

- 相关度实现简单、可离线重放，但不宣称语义理解；BM25、Vector 和 Rerank 留给后续批次。
- 审核状态在业务数据库中持久化，便于跨进程查询；Graph Checkpoint 只保存工作流快照，不承担文献审计。
- 只允许项目级批准，不把全局文献“认证”为所有项目通用证据，避免范围泄漏。

## 验证

`tests/integration/test_m4_project_document_review.py` 验证迁移升级/回滚、项目隔离、排序、批准/拒绝、失败文献门禁和理由校验。测试使用合成/脱敏条目，不构造真实论文事实。
