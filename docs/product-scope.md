# 产品范围与非目标

## 定位

研迹 ScholarTrace 是从研究问题、文献证据、数据与实验，到论文和真实部署的可追溯科研工作台。系统维护的核心链路是：

```text
文献 → 证据 → 方法 → 数据 → 实验 → 指标 → 图表 → 论文结论 → 真实部署
```

首个贯穿场景是农业视觉科研项目，覆盖果实/害虫目标检测与计数、作物病害分类等可审计任务。

## 必须做到

- 跨会话保存结构化科研状态和版本历史；
- 让引用、Claim、指标、图表和交付物能够回到真实来源；
- 对正式方案、数据修改、实验启动、论文发布和部署设置人工确认；
- 以确定性工具执行解析、校验、计算、制图和打包；
- 保存失败、限制和证据缺口，不把不确定内容包装为结论；
- 生成可复现、可部署、可审计的工程交付包。

## 明确非目标

- 不做通用自主科研 Agent，也不保证自动发现原创科学创新；
- 不自动投稿、公开发布、下载受版权限制全文或执行破坏性命令；
- 不让 LLM 直接修改原始标注、模型权重或论文最终版本；
- 不在没有真实实验时生成结果数字、统计显著性、结果图或肯定性结论；
- 不把文献库噪声默认当作项目证据；
- 不把训练日志临时值当作最终独立评估指标；
- 不把合成、Fixture、离线或实验室结果称为真实现场验证；
- 不在早期引入复杂多租户、IM 平台、Skill 市场或 Supervisor 多 Agent。

## M0 能力声明

M0 只建立仓库、治理契约、脱敏 Fixture、测试和 CI。后续能力即使在文档中出现，也只代表计划，不代表当前已实现。
